# DataGuard — Deployment Guide

DataGuard supports two deployment architectures. Choose one:

| | **Netlify** | **Docker / VPS** |
|---|---|---|
| Hosting | Netlify CDN | Any Linux VPS (Ubuntu 22.04+) |
| Backend | Netlify Functions (serverless) | FastAPI + Celery in Docker |
| Database | Supabase (managed Postgres) | Postgres in Docker (or RDS) |
| Auth | GitHub OAuth via Functions | GitHub OAuth via FastAPI |
| Playwright scans | ✗ (not supported in Functions) | ✓ (Celery workers) |
| Cost | Free tier available | ~$10–20/mo for 2-vCPU/4GB server |
| Best for | Demos, low-traffic, quick launch | Full-featured, automated opt-outs |

---

## Path A — Netlify Deployment

### 1. Supabase setup

1. Create a project at [supabase.com](https://supabase.com)
2. Go to **SQL Editor** and run the contents of `supabase/schema.sql`
3. Note your **Project URL**, **Publishable key**, and **Service Role key**

### 2. GitHub OAuth App

1. Go to github.com → Settings → Developer settings → OAuth Apps → **New OAuth App**
2. Set **Authorization callback URL** to:
   ```
   https://yoursite.netlify.app/api/v1/auth/github/callback
   ```
3. Note the **Client ID** and generate a **Client Secret**

### 3. Deploy to Netlify

```bash
# Connect repo in Netlify UI, or use the CLI:
npm install -g netlify-cli
netlify deploy --build
```

### 4. Set environment variables in Netlify UI

Go to **Site settings → Environment variables** and add:

| Variable | Value |
|---|---|
| `SECRET_KEY` | 64+ char random string — run `python backend/scripts/generate_key.py --print-only` |
| `GITHUB_CLIENT_ID` | From GitHub OAuth App |
| `GITHUB_CLIENT_SECRET` | From GitHub OAuth App |
| `GITHUB_REDIRECT_URI` | `https://yoursite.netlify.app/api/v1/auth/github/callback` |
| `FRONTEND_URL` | `https://yoursite.netlify.app` |
| `SUPABASE_URL` | From Supabase project settings |
| `SUPABASE_SERVICE_ROLE_KEY` | From Supabase project settings → API |
| `HIBP_API_KEY` | From haveibeenpwned.com/API/Key |
| `VITE_SUPABASE_URL` | Same as `SUPABASE_URL` |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Supabase anon/publishable key |

### 5. Verify

```
curl https://yoursite.netlify.app/api/v1/auth/github
# Should redirect to GitHub — 302 response
```

## Path B — Docker / VPS Deployment

### 1. Server setup

- Ubuntu 22.04 LTS, minimum 2 vCPU / 4 GB RAM
- Install Docker + Docker Compose v2:
  ```bash
  curl -fsSL https://get.docker.com | sh
  apt-get install docker-compose-plugin
  ```
- Open ports **80** and **443** in your firewall / cloud security group

### 2. Clone and prepare

```bash
git clone https://github.com/nyakanne/theclipart.git dataguard
cd dataguard
chmod +x scripts/setup.sh
sudo ./scripts/setup.sh
```

The setup script checks prerequisites, creates `backend/.env`, generates `SECRET_KEY`, and creates `nginx/ssl/`.

### 3. SSL certificate

**Option A — Let's Encrypt (production)**
```bash
apt-get install certbot
certbot certonly --standalone -d yourdomain.com
cp /etc/letsencrypt/live/yourdomain.com/fullchain.pem nginx/ssl/cert.pem
cp /etc/letsencrypt/live/yourdomain.com/privkey.pem   nginx/ssl/key.pem
```

**Option B — Self-signed (staging/testing only)**
```bash
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout nginx/ssl/key.pem -out nginx/ssl/cert.pem \
  -subj "/CN=yourdomain.com"
```

### 4. Fill in backend/.env

Open `backend/.env` and replace every `REPLACE_ME` value:

| Variable | How to get it |
|---|---|
| `SECRET_KEY` | Already generated by `setup.sh` |
| `POSTGRES_PASSWORD` | Strong random string — `openssl rand -hex 32` |
| `REDIS_PASSWORD` | Strong random string — `openssl rand -hex 32` |
| `FLOWER_PASSWORD` | Strong random string |
| `GITHUB_CLIENT_ID` | GitHub → Settings → Developer settings → OAuth Apps |
| `GITHUB_CLIENT_SECRET` | Same OAuth App |
| `GITHUB_REDIRECT_URI` | `https://yourdomain.com/api/v1/auth/github/callback` |
| `FRONTEND_URL` | `https://yourdomain.com` |
| `CORS_ORIGINS` | `https://yourdomain.com` |
| `HIBP_API_KEY` | [haveibeenpwned.com/API/Key](https://haveibeenpwned.com/API/Key) |
| `KMS_KEY_ID` | AWS KMS key ARN (required when `APP_ENV=production`) |
| `SES_FROM_EMAIL` | Verified SES sender address |
| `DD_API_KEY` | Datadog → Organization Settings → API Keys |

Also set `APP_ENV=production` once all values are filled in.

### 5. Update nginx server_name

Edit `nginx/nginx.conf` and replace the two `server_name _;` placeholders:
```nginx
server_name yourdomain.com www.yourdomain.com;
```

### 6. GitHub OAuth App callback

Create a GitHub OAuth App with callback URL:
```
https://yourdomain.com/api/v1/auth/github/callback
```

### 7. Run database migrations

```bash
docker compose --env-file backend/.env run --rm backend alembic upgrade head
```

### 8. Deploy

```bash
docker compose --env-file backend/.env --profile production up -d --build
```

### 9. Verify

```bash
curl https://yourdomain.com/health               # → {"status":"ok","env":"production"}
curl https://yourdomain.com/api/v1/auth/github   # → 302 redirect to github.com
docker compose ps                                # all services: healthy / running
```

## Local Dev (no Docker, no infrastructure)

```bash
# Terminal 1 — demo backend (in-memory, no Postgres/Redis/AWS needed)
cd backend
DEMO_MODE=true python -m uvicorn demo_main:app --host 127.0.0.1 --port 8000 --reload

# Terminal 2 — frontend
cd frontend
npm run dev
# Open http://localhost:3000
```

The demo backend returns realistic mock scan data. No secrets, databases, or cloud services required.

## Docker Dev (full stack, HTTP only)

```bash
cp backend/.env.example backend/.env
# Fill in: SECRET_KEY, POSTGRES_PASSWORD, REDIS_PASSWORD, FLOWER_PASSWORD, GITHUB_* vars

docker compose --env-file backend/.env --profile dev up -d
# Open http://localhost
```

## Pre-Launch Checklist

### Secrets
- [ ] `SECRET_KEY` is 64+ chars, not a placeholder
- [ ] No real values in `.env.example`, `frontend/.env.example`, or any other committed file
- [ ] `backend/.env` is in `.gitignore` (it is — verify with `git status`)
- [ ] `netlify/functions/node_modules/` is in `.gitignore` (it is)
- [ ] GitHub OAuth secret is **not** committed
- [ ] Supabase service role key is **not** committed

### Database
- [ ] **Netlify path**: Supabase schema (`supabase/schema.sql`) has been run in SQL Editor
- [ ] **Netlify path**: `users` and `scans` tables exist, RLS is enabled
- [ ] **Docker path**: `alembic upgrade head` has been run successfully
- [ ] Production `DATABASE_URL` / Supabase URL points to real instance

### Auth (GitHub OAuth)
- [ ] GitHub OAuth App created with exact callback URL
- [ ] `GITHUB_REDIRECT_URI` matches the OAuth App callback exactly (no trailing slash)
- [ ] `FRONTEND_URL` set to production domain, no trailing slash

### Backend
- [ ] `APP_ENV=production` in production `.env`
- [ ] `CORS_ORIGINS` set to production domain only (not `*`, not localhost)
- [ ] `FRONTEND_URL` set to production domain (startup check will catch localhost)
- [ ] `HIBP_API_KEY` set — breach scanning is a no-op without it
- [ ] `KMS_KEY_ID` set — required when `APP_ENV=production`

### Opt-Out Automation
- [ ] `ALLOW_REAL_OPT_OUTS=false` until ALL of the following are true:
  - [ ] SES domain verification complete (check SES console → Verified identities)
  - [ ] SES account out of sandbox (request production access in AWS support)
  - [ ] Removal email delivery tested to a real inbox end-to-end
- [ ] `SES_FROM_EMAIL` is a verified SES identity (not a placeholder)

### HTTPS / Nginx (Docker/VPS path)
- [ ] SSL cert at `nginx/ssl/cert.pem`, key at `nginx/ssl/key.pem`
- [ ] `server_name` in `nginx/nginx.conf` replaced with real domain
- [ ] Port 443 open in firewall / security group
- [ ] HTTP→HTTPS redirect works: `curl -I http://yourdomain.com` → 301
- [ ] HSTS header present: `curl -I https://yourdomain.com | grep Strict`

### Netlify path
- [ ] All env vars set in Netlify UI (not hardcoded in source)
- [ ] `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` set for frontend build
- [ ] `FRONTEND_URL` set so CORS headers lock down cross-origin access
- [ ] Build succeeds without Netlify secrets-scan errors

### Datadog (optional but recommended)
- [ ] `DD_API_KEY` set to a real key
- [ ] Datadog site set to your region (default: `us3.datadoghq.com`)
- [ ] Frontend RUM app created; `VITE_DD_APPLICATION_ID` + `VITE_DD_CLIENT_TOKEN` set
- [ ] Frontend rebuilt after setting RUM vars: `docker compose build frontend`

### DNS
- [ ] A record for `yourdomain.com` → server IP
- [ ] (Optional) CNAME `www` → `yourdomain.com`
- [ ] DNS propagated: `dig +short yourdomain.com` returns server IP

## Useful Commands

```bash
# View logs
docker compose logs -f backend
docker compose logs -f nginx

# Tail all logs
docker compose logs -f --tail=100

# Restart a single service after config change
docker compose restart backend

# Rebuild and redeploy backend only
docker compose --env-file backend/.env --profile production up -d --build backend

# Run DB migrations manually
docker compose exec backend alembic upgrade head

# Check nginx config syntax before deploying
docker run --rm -v $(pwd)/nginx/nginx.conf:/etc/nginx/nginx.conf:ro nginx:1.25-alpine nginx -t

# Renew Let's Encrypt cert (add to cron: 0 3 * * * certbot renew --quiet && docker compose restart nginx)
certbot renew --quiet
cp /etc/letsencrypt/live/yourdomain.com/fullchain.pem nginx/ssl/cert.pem
cp /etc/letsencrypt/live/yourdomain.com/privkey.pem   nginx/ssl/key.pem
docker compose restart nginx

# Generate a new SECRET_KEY
python backend/scripts/generate_key.py --print-only
```
